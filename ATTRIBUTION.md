# Attribution

## AI Development Tools

Claude Code (Anthropic) was used during development. Each AI-generated function, class, or file is also marked in its docstring or file header.

- Repository scaffold (directory layout, placeholder README/SETUP/ATTRIBUTION, `.gitignore`): generated by Claude Code from the course's required structure.
- `docs/design.md`: drafted by Claude Code from my project direction. I chose the format (Gen 2 OU), the algorithms, the hidden-information research question and the memory stretch goal. Claude Code proposed the three measurements of the research question, checked the cited papers, and wrote the text. Claude Code later updated the environment, teams, encoding and reward sections to match the implementation.
- `src/teams.py`: generated by Claude Code. Debugged during the first test run: the team files end in blank lines, which poke-env's parser read as a seventh empty Pokemon, and the server rejected those teams. The loader now drops empty entries and checks each team has exactly 6.
- `src/encoding.py`: generated by Claude Code, including the feature layout, the move-role groups and the oracle slot ordering. Move priority was first left unscaled and pushed features outside the observation bounds; it is now divided by 3.
- `src/env.py`: generated by Claude Code, including the potential-based capped shaping reward.
- `src/evaluate.py` and `src/run_baselines.py`: generated by Claude Code.
- Turn cap in `src/env.py` (`MAX_TURNS`, `calc_term_trunc`): added by Claude Code after the first DQN test run, where 6 of 11 early battles passed 200 turns and two hit Showdown's 1000-turn tie from Rest and Leftovers stalling. Both training scripts bootstrap through a turn-cap cutoff instead of treating it as a terminal state.
- `src/dqn.py` and `src/train_dqn.py`: generated by Claude Code (Q-network with optional dueling head, replay buffer storing next-state masks, masked Double DQN target, epsilon schedule, training loop with validation checkpointing).
- `src/ppo.py` and `src/train_ppo.py`: generated by Claude Code (shared-trunk actor-critic, masked categorical policy, GAE, clipped surrogate objective, training loop with validation checkpointing).
- `src/run_log.py`: generated by Claude Code.
- `load_agent` in `src/evaluate.py`: generated by Claude Code.
- `Curriculum` in `src/env.py` and the curriculum options in both training scripts: generated by Claude Code after iteration 0 (`docs/iteration-log.md`) showed neither agent learning against the heuristic opponent alone.
- Iteration 4 changes, generated by Claude Code after the information-gap runs showed every DQN run collapsing once it reached the heuristic stage: the mixed curriculum (`--mixed`, `Curriculum.training_opponent` in `src/env.py`), the `--reward` option for shaping weights, the switch from a plain to a discounted potential difference in `Gen2Env.calc_reward`, the per-battle opponent column in the episode logs, and `slurm/iteration4.txt`. The reward section of `docs/design.md` was rewritten to match. The idea of reshaping the reward to separate close losses from routs came from me; Claude Code pointed out that the existing potential-based shaping already rewarded damage and margin of victory, only at a small weight, and proposed raising the weights over adding new bonus terms.
- Cluster support: `SHOWDOWN_PORT` in `src/env.py`, `override_config` in `src/run_log.py` with the `--config` option and single-thread setting in both training scripts, and `slurm/train_array.sbatch` with `slurm/sweep.txt` and `slurm/info_gap.txt`, generated by Claude Code. Debugged in a local test of two simultaneous tasks: servers sharing one Showdown folder raced on rewriting its data files at startup, so each task now runs a private copy on local disk, bound to localhost.
- `src/evaluate_runs.py`: generated by Claude Code to evaluate the final checkpoints of the hyperparameter sweep under one protocol, because runs that never reached the last curriculum stage have no `best.pt`, and the in-training evaluations were made against different opponents at different steps.
- `docs/iteration-log.md`: written by Claude Code from the measured training logs.
- `src/training.py`: generated by Claude Code to remove code duplicated between `src/train_dqn.py` and `src/train_ppo.py`. It holds the shared command line (`parse_training_args`) and `TrainingRun`, which owns the run folder, the episode and evaluation logs, and the periodic validation that saves `best.pt` and advances the curriculum. `RESULTS_DIR` moved from `src/run_baselines.py` to `src/run_log.py` at the same time. Behavior is unchanged apart from the DQN progress line no longer printing epsilon, which is still logged per episode in `episodes.csv`. Checked with short runs of both scripts that forced a curriculum advance under `--mixed`.
- Team split in `data/teams/` and `data/README.md`: split and documented by Claude Code.
- `src/build_teams.py`: generated by Claude Code to make the team split reproducible. It downloads both team sets at a pinned dataset revision and redoes the seeded split and the ladder filters; its output was checked to match the committed `data/teams/` exactly.
- Ladder teams in `data/teams/train/`: downloaded, validated with Showdown's team validator, filtered for duplicates and overlap with held-out teams, and documented by Claude Code for iteration 2.
- Iteration 5 changes, generated by Claude Code:
  - The held-out ladder pools (`split_ladder` in `src/build_teams.py`) and the `pool` option in `src/teams.py`, `src/env.py`, `src/evaluate.py`, `src/run_baselines.py` and `src/evaluate_runs.py`. The original 11 / 4 / 3 split of the expert teams was Claude Code's. When the ladder teams were added to training in iteration 2, Claude Code left validation and test at four and three expert teams without flagging it. I caught the problem while reviewing iteration 4. A first version held out 250 ladder teams per split, and Claude Code then found that they formed only 73 compositions, one of them 75 teams. Holding out whole compositions with a cap of three teams each replaced it.
  - Checkpoint selection against the heuristic and early stopping (`EvalSettings`, `TrainingRun.select` and `TrainingRun.out_of_patience` in `src/training.py`). I asked for the best checkpoint of each run to be reported in place of the last one, for a 2M-step cap, and for early stopping. Claude Code chose the 600K patience from the longest waits between new bests in earlier PPO runs (up to 530K), and proposed starting the countdown only on a run's final curriculum stage, since DQN runs that are still on max_power can advance as late as 380K.
  - `known_type` in `src/encoding.py`. While checking Hidden Power before freezing the code, Claude Code found that poke-env reports a revealed opponent Hidden Power as a Normal-type attack, which put a false Normal attack flag and false matchups into realistic observations. It is now treated as a move of unknown type.
  - `slurm/final.txt` and the 12-hour job limit in `slurm/train_array.sbatch`.

## External Libraries

- [poke-env](https://github.com/hsahovic/poke-env) 0.17.0: Showdown client, battle state tracking, the `SinglesEnv` Gymnasium environment, action masks, and the scripted `RandomPlayer`, `MaxBasePowerPlayer` and `SimpleHeuristicsPlayer` opponents.
- [Pokemon Showdown](https://github.com/smogon/pokemon-showdown): the battle simulator, run as a local server.
- PyTorch 2.15, Gymnasium 1.4, NumPy 2.5.

## Datasets

- Gen 2 OU teams from Metamon's team dataset, `competitive` and `hl_05_26` sets ([jakegrigsby/metamon-teams](https://huggingface.co/datasets/jakegrigsby/metamon-teams), Grigsby et al., RLC 2025). Details and split in `data/README.md`.
